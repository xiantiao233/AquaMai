# Mai2Touch 通讯协议规范

## 一、物理层

| 参数 | 值 |
|------|-----|
| 接口 | UART |
| 波特率 | 9600 bps |
| 数据位 | 8 |
| 校验位 | 无 |
| 停止位 | 1 |

---

## 二、帧格式

ASCII 文本协议，以起始符和终止符定界，无长度字段，无校验。

| 方向 | 起始符 | 终止符 | 格式 |
|------|--------|--------|------|
| 主机 → 设备 | `{` (0x7B) | `}` (0x7D) | `{xxxx}` |
| 设备 → 主机 | `(` (0x28) | `)` (0x29) | `(xxxx)` |

### 解析规则

- 收到 `{` 时清空缓冲区，开始接收
- 收到 `}` 时结束接收，当前缓冲区内数据为一帧命令
- 帧之间无间隔要求，`{` 出现即自动重置

---

## 三、命令定义

所有命令均为固定 5 字节 payload，命令标识位于**第 4 字节**（即 `packet[3]`）。

### 3.1 RSET — 复位

```
主机发送: {RSET}
Hex:      7B 52 53 45 54 7D
```

设备收到后执行硬件初始化，**无需回复**。

### 3.2 HALT — 停止触摸

```
主机发送: {HALT}
Hex:      7B 48 41 4C 54 7D
```

设备收到后**立即停止发送触摸数据**，进入配置待命状态。**无需回复**。

### 3.3 STAT — 开始触摸

```
主机发送: {STAT}
Hex:      7B 53 54 41 54 7D
```

设备收到后**开始周期性发送触摸数据**。上电默认不发送，必须收到此命令才启动。**无需回复**。

### 3.4 Ratio — 设置感度比例 (回声)

```
主机发送: {LAr2}     (示例, 实际值可变)
Hex:      7B 4C 41 72 32 7D
```

设备回复与接收内容完全相同的帧：

```
设备回复: (LAr2)
Hex:      28 4C 41 72 32 29
```

### 3.5 Sens — 设置灵敏度 (回声)

```
主机发送: {LAk.}     (示例, 实际值可变)
Hex:      7B 4C 41 6B 1E 7D
```

设备回复与接收内容完全相同的帧：

```
设备回复: (LAk.)
Hex:      28 4C 41 6B 1E 29
```

## 四、触摸数据格式

设备在收到 `{STAT}` 后开始周期性发送。

### 帧结构 (9 字节)

```
Byte:  [0]   [1] [2] [3] [4] [5] [6] [7]   [8]
       '('                                       ')'
             │  7 字节触摸数据  │
```

中间 7 个字节编码 35 bits 触摸状态（有效 34 bits，最高 1 bit 未使用）：

```
字节 [1] bits[4:0] ← 触摸区  0 ~  4
字节 [2] bits[4:0] ← 触摸区  5 ~  9
字节 [3] bits[4:0] ← 触摸区 10 ~ 14
字节 [4] bits[4:0] ← 触摸区 15 ~ 19
字节 [5] bits[4:0] ← 触摸区 20 ~ 24
字节 [6] bits[4:0] ← 触摸区 25 ~ 29
字节 [7] bits[4:0] ← 触摸区 30 ~ 33  (仅低 4 bit 有效)
```

每个 bit 含义：`0 = 未触摸`，`1 = 触摸`

### 示例

仅 A1 按下：

```
发送: 28 01 00 00 00 00 00 00 29
解码:
  字节1: 00000001 → bit0=1 (A1 触摸)
  字节2~7: 全 0
```

A1 + B5 同时按下：

```
发送: 28 01 00 04 00 00 00 00 29
解码:
  字节1: 00000001 → bit0=1 (A1)
  字节3: 00000100 → bit12=1 (B5)
```

## 五、触摸区映射

**Mai2Touch 协议使用游戏内部触摸区编号顺序（A→E，1→8），而非物理通道映射。**

35-bit 位掩码的 bit 0 ~ bit 33 与触摸区对应关系：

```
bit  0 → A1      bit  8 → B1      bit 16 → C1      bit 26 → E1
bit  1 → A2      bit  9 → B2      bit 17 → C2      bit 27 → E2
bit  2 → A3      bit 10 → B3                        bit 28 → E3
bit  3 → A4      bit 11 → B4                        bit 29 → E4
bit  4 → A5      bit 12 → B5                        bit 30 → E5
bit  5 → A6      bit 13 → B6                        bit 31 → E6
bit  6 → A7      bit 14 → B7                        bit 32 → E7
bit  7 → A8      bit 15 → B8                        bit 33 → E8
                       
                 D1~D8: bit 18 ~ bit 25
```

> **注意**：这是游戏引擎内部编号，与硬件 PhysicalToLogicalMap（物理通道→逻辑区映射表）是两套独立的映射体系。PhysicalToLogicalMap 仅用于 tenodata/70字节二进制协议。Mai2Touch 协议直接使用游戏编号。

## 六、状态机

```
           上电 / {RSET}
                │
                ▼
        ┌──────────────┐
        │  待命状态     │
        │  (不发送数据)  │
        └──────┬───────┘
               │ 收到 {STAT}
               ▼
        ┌──────────────┐
        │  运行状态     │
        │  (周期性发送   │
        │   触摸数据)    │
        └──────┬───────┘
               │ 收到 {HALT}
               ▼
        ┌──────────────┐
        │  待命状态     │
        │  (停止发送)   │
        └──────────────┘
```

**设备上电后默认处于待命状态，不发送触摸数据。** 必须收到 `{STAT}` 才开始发送。

| 状态 | 触发 | 行为 |
|------|------|------|
| **待命** | 上电 / `{HALT}` / `{RSET}` | 可接收命令，**不发送**触摸数据 |
| **运行** | `{STAT}` | 周期性发送触摸数据帧 |

---

## 七、接收处理流程

```
每周期:
  1. 检查串口缓冲区是否有数据
  2. 逐字节读取:
     - 遇到 '{' → 清空缓冲区，开始记录
     - 遇到 '}' → 帧结束，解析命令
     - 其他字节 → 追加到缓冲区
  3. 帧长度为 5 字节时:
     - 检查 packet[3] 确定命令
     - 执行对应操作
     - 清空缓冲区
```

## 八、命令速查表

| 命令 | 帧 hex | 方向 | 是否需要回复 | 回复内容 |
|------|--------|------|:----------:|---------|
| RSET | `7B 52 53 45 54 7D` | 收 | 否 | — |
| HALT | `7B 48 41 4C 54 7D` | 收 | 否 | — |
| STAT | `7B 53 54 41 54 7D` | 收 | 否 | — |
| Ratio | `7B L/R sensor 72 ratio 7D` | 收 | **是** | `(cmd)` 原样回声 |
| Sens | `7B L/R sensor 6B sens 7D` | 收 | **是** | `(cmd)` 原样回声 |
| Touch | `28 7×5bits 29` | 发 | — | — |
