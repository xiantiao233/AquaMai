# PSoC 触摸控制器技术文档

## 一、系统概述

PSoC (Programmable System-on-Chip) 作为自电容触摸传感器控制器，通过 EZI2C 从机接口与 STM32 主控通讯。每个 PSoC 管理 17 个物理触摸通道，两个 PSoC 合计覆盖 34 通道。

```
┌──────────────────┐         ┌──────────────────┐
│   PSoC Device 0  │  I2C    │   PSoC Device 1  │
│   地址: 0x08     │◄──────►│   地址: 0x09     │
│   通道: 0 ~ 16   │  STM32  │   通道: 17 ~ 33  │
└──────────────────┘         └──────────────────┘
```

---

## 二、EZI2C 接口定义

### 2.1 I2C 地址

| 设备 | 7-bit 地址 | 8-bit 写地址 | 通道范围 |
|------|-----------|-------------|---------|
| Device 0 | 0x08 | 0x10 | 0 ~ 16 (17通道) |
| Device 1 | 0x09 | 0x12 | 17 ~ 33 (17通道) |

### 2.2 内存映射 (Memory Map)

| 偏移 | 大小 | 寄存器名 | 读写 | 说明 |
|------|------|---------|------|------|
| 0x00 | 1 | STATUS | R/W | 状态/命令寄存器 |
| 0x01 ~ 0x22 | 34 | RAW_DATA | R | 触摸原始数据 (17ch × 2byte) |
| 0x56 (86) | 68 | CONFIG | W | 通道配置参数 (17ch × 4byte) |

### 2.3 完整 I2C 数据帧

**读取 (35 bytes):**
```
[0]     Status       状态字节
[1..2]  Channel 0    16-bit 原始电容值 (little-endian)
[3..4]  Channel 1
 ...
[33..34] Channel 16
```

**写入配置 (68 bytes):**
```
[0..16]   Resolution  17 通道分辨率 (每通道 1 byte)
[17..33]  Mod IDAC    17 通道调制电流 (每通道 1 byte)
[34..50]  Sense Div   17 通道感应分频 (每通道 1 byte)
[51..67]  Mod Div     17 通道调制分频 (每通道 1 byte)
```

## 三、状态寄存器 (STATUS @ 0x00)

### 3.1 状态码定义

| 值 | 方向 | 含义 |
|----|------|------|
| 0x00 | PSoC→STM32 | **崩溃/重启** — PSoC 异常复位，需重新配置和校准 |
| 0x01 | STM32→PSoC | **启动校准** — 写入此值触发 PSoC 开始自动基线校准 |
| 0x02 | PSoC→STM32 | **校准完成** — 所有通道基线已建立，可以进入正常扫描 |
| 0x11 | PSoC→STM32 | **校准进度 1/5** — 正在进行第一阶段校准 |
| 0x12 | PSoC→STM32 | **校准进度 2/5** |
| 0x13 | PSoC→STM32 | **校准进度 3/5** |
| 0x14 | PSoC→STM32 | **校准进度 4/5** |
| 0x15 | PSoC→STM32 | **校准进度 5/5** — 最后阶段 |

### 3.2 校准流程

```
STM32                               PSoC
  │                                   │
  │ I2C Write CONFIG (68 bytes)       │
  │──────────────────────────────────►│ 接收配置参数
  │                                   │
  │ I2C Write STATUS = 0x01           │
  │──────────────────────────────────►│ 启动校准流程
  │                                   │
  │ I2C Read STATUS                   │
  │◄──────────────────────────────────│ 0x11 (进度 1/5)
  │ I2C Read STATUS                   │
  │◄──────────────────────────────────│ 0x12 (进度 2/5)
  │        ... 轮询每 100ms ...        │
  │ I2C Read STATUS                   │
  │◄──────────────────────────────────│ 0x15 (进度 5/5)
  │ I2C Read STATUS                   │
  │◄──────────────────────────────────│ 0x02 (校准完成)
  │                                   │
  │        进入 RUNNING 模式           │
```

## 四、配置参数详解

### 4.1 参数列表

| 参数 | 字节位置 | 每通道 | 说明 |
|------|---------|--------|------|
| **Res** (Resolution) | CONFIG[0..16] | 1 byte | 扫描分辨率，控制 ADC 采样精度。值越大分辨率越高，但扫描时间越长 |
| **Mod** (Modulation IDAC) | CONFIG[17..33] | 1 byte | 调制电流源大小，控制激励信号强度。值越大信号越强，但功耗和噪声也增加 |
| **Sns** (Sense Divider) | CONFIG[34..50] | 1 byte | 感应分频比，控制感应通道的增益。值越大灵敏度越低 |
| **Div** (Mod Divider) | CONFIG[51..67] | 1 byte | 调制分频比，控制调制频率。与 Mod 配合调整信噪比 |

### 4.2 默认值参考 (来自 HardwareConfig)

| 区块 | 通道范围 | Res | Mod | Sns | Div | DetGroup |
|------|---------|-----|-----|-----|-----|----------|
| A | 外圈大面积 | 12 | 15 | 2 | 2 | A |
| B | 内圈 | 10 | 25 | 4 | 4 | B |
| C | 特殊功能区 | 12 | 30 | 4 | 4 | C |
| D | 边缘小面积 | 8 | 10 | 2 | 2 | D |
| E | 边缘小面积 | 8 | 8 | 2 | 2 | E |

每个物理通道的具体参数由 `HardwareConfig.PhysicalToLogicalMap` 按块查找对应的 `ScanParams` 确定。

### 4.3 参数下发映射

上位机按物理通道 0~33 顺序排列 136 字节配置，STM32 拆包后路由到对应 PSoC：

```
上位机 136 字节 = [Res[0..33]] + [Mod[0..33]] + [Sns[0..33]] + [Div[0..33]]

PSoC 0 (通道 0~16):   offset = 0
  CONFIG[0..16]   ← 上位机
  CONFIG[17..33]  ← 上位机
  CONFIG[34..50]  ← 上位机
  CONFIG[51..67]  ← 上位机

PSoC 1 (通道 17~33):  offset = 17
  CONFIG[0..16]   ← 上位机
  CONFIG[17..33]  ← 上位机
  CONFIG[34..50]  ← 上位机
  CONFIG[51..67]  ← 上位机
```

## 五、原始触摸数据格式

### 5.1 单个通道数据

每通道 16-bit unsigned short (little-endian)：
```
raw = (byte[2n+1] | (byte[2n+2] << 8))
```

值范围：0 ~ 65535，表示该通道的自电容测量原始值。

### 5.2 I2C 读取 → CDC 上行组装

```
PSoC 0 (35 bytes):            CDC TX frame (70 bytes):
  STATUS                       [0]  = 0x00 (running status)
  Ch0  Lo, Ch0  Hi            [1]  = Ch0  Lo
  Ch1  Lo, Ch1  Hi            [2]  = Ch0  Hi
  ...                          [3]  = Ch1  Lo
  Ch16 Lo, Ch16 Hi             ...
                                [33] = Ch16 Lo
PSoC 1 (35 bytes):             [34] = Ch16 Hi
  STATUS (丢弃)                [35] = Ch17 Lo
  Ch17 Lo, Ch17 Hi             [36] = Ch17 Hi
  ...                          ...
  Ch33 Lo, Ch33 Hi             [67] = Ch33 Lo
                                [68] = Ch33 Hi
                                [69] = Checksum
```

> **注意**：PSoC 的 STATUS 字节（索引 0）在上行打包时被丢弃，每个 PSoC 贡献 34 字节有效载荷。

### 5.3 C# 端处理链路

```
CDC 70 bytes
  → SerialThreadManager (校验 + IIR 滤波)
    → TouchStateProcessor (校准基线 + 通道映射)
      → ButtonDetector (diff/diff_deriv 计算 + 状态机判定)
        → currentTouchMask → 游戏引擎
```

## 六、电气与时序特性

### 6.1 I2C 时序参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 速率 | Standard (100kHz) | `HAL_I2C_IsDeviceReady` timeout = 10ms |
| 配置写入超时 | 100ms | `HAL_I2C_Mem_Write` 超时 |
| 读数据超时 | 10ms | `HAL_I2C_Mem_Read_IT` 超时 |
| 轮询间隔 (运行) | 8ms | 两个 PSoC 交替读取 |
| 校准轮询间隔 | 100ms | 防止过快轮询卡死 PSoC |
| 配置写入后延时 | 5ms | 给 PSoC 缓冲时间 |

### 6.2 上电初始化时序

| 阶段 | 最小耗时 | 说明 |
|------|---------|------|
| PSoC 上电稳定 | ~50ms | 硬件复位 + 固件启动 |
| I2C 设备探测 | 10ms × N | 轮询直到 >=1 个设备响应 |
| 等待上位机配置 | 不确定 | STM32 持续发 0x01 直到 PC 下发 |
| 配置写入 | ~12ms | 2 × (68B 写 + 5ms 延时 + 1B 写) |
| PSoC 校准 | ~500ms~2s | 5 阶段，每 100ms 轮询 |
| **合计** | **~3s** | 断电到可运行 |

### 6.3 运行时数据率

- CDC 推流周期: **5ms (200Hz)**
- I2C 轮询间隔: **8ms (125Hz)**
- 实际吞吐: 每 8ms 读取一个 PSoC，两个 PSoC 交替 → 每个 PSoC 约 **62.5Hz** 刷新率
- CDC 上行复用同一组数据（直到下次 I2C 更新），实际有效刷新率为 **~125Hz**（两个 PSoC 的数据合并）

## 七、异常处理

### 7.1 PSoC 崩溃恢复

```
触发条件: STATUS == 0x00
恢复流程:
  1. STM32 切换到 WAIT_HOST_CONFIG
  2. 重新向 PC 请求配置 (CDC status=0x01)
  3. PC 重新下发 139 字节配置
  4. STM32 重新写入 PSoC 并触发校准
  5. 校准完成后恢复正常运行
```

### 7.2 I2C 通讯错误

- **读错误**: 回调 `HAL_I2C_ErrorCallback` → 设置 `i2c_transfer_error` → 跳过该设备本轮，下次重试
- **写错误**: 配置写入失败不阻塞状态机，PSoC 未收到配置 → 后续校准阶段状态为 0x00 → 自动退回重配

### 7.3 上位机配置校验失败

- STM32 校验 139 字节配置帧的 checksum
- 校验失败 → 丢弃该帧，等待下一帧（PC 端 `SendHardwareConfig` 有 1 秒防抖间隔）
- 不影响当前状态，STM32 继续发送 0x01 请求配置

## 八、与原始 SEGA 协议的区别

| 特性 | 原始 SEGA (IO.NewTouchPanel) | 自定义 PSoC 方案 |
|------|---------------------------|-----------------|
| 物理层 | 未知串口协议 | USB CDC (虚拟串口) |
| 帧格式 | ASCII 文本 (`{cmd}` / `(data)`) | 二进制帧 (70/139 bytes) |
| 校验 | 无 | 累加和取低 8 位 |
| 触摸数据 | 7 bytes 位掩码 (已判定) | 34 × 16-bit 原始电容值 |
| 配置方式 | 逐通道 ASCII 命令 | 批量二进制下发 |
| 灵敏度 | 仅 ratio/sens 两级 | 4 参数独立调整 (Res/Mod/Sns/Div) |
| 判定位置 | PSoC/硬件端 | PC 端软件算法 (ButtonDetector) |
| 校准 | 未知 | 5 阶段自动基线校准 |
